# Headless E2E UI & Visual Verification

A standardized playbook for authoring and running headless browser tests and visual verification suites using Playwright in this Next.js project.

---

## Toolchain Commands

| Action | Command | Purpose |
| :--- | :--- | :--- |
| **Run All E2E Specs** | `npx playwright test` | Executes all specs in `tests/visual/` headlessly |
| **Run Single Spec File** | `npx playwright test tests/visual/<file>.spec.ts` | Targeted execution during development |
| **Headed Mode** | `npx playwright test tests/visual/<file>.spec.ts --headed` | Runs browser visibly for interactive debugging |
| **Update Visual Snapshots** | `npx playwright test --update-snapshots` | Re-baselines snapshot comparisons |
| **View Test HTML Report** | `npx playwright show-report` | Inspects traces, videos, and screenshots |

## Authoring Robust E2E Specs

### 1. Robust Locators (Apple Design & Accessibility-First)
Always prioritize user-facing accessible locators over brittle CSS classes:

```ts
// Preferred: By accessible role & label
await page.getByRole('button', { name: 'Complete Order' }).click();
await page.getByLabel('First Name').fill('Jonathan');

// Secondary: By test id or semantic role
await page.getByTestId('cart-drawer').toBeVisible();

// Avoid: Brittle CSS classes generated by Tailwind or hashed CSS modules
// await page.locator('.btn-primary-3x').click(); // AVOID!
```

### 2. Handling Motion & Spring Animations
Because this application utilizes spring physics (`motion/react` with spring damping), never use arbitrary `setTimeout` or sleep. Instead, rely on Playwright's auto-waiting assertions:

```ts
// Auto-waits for element to settle and reach visibility
await expect(page.locator('dialog[open]')).toBeVisible();

// When verifying modal transitions or drawer entrances:
const drawer = page.getByRole('dialog');
await expect(drawer).toHaveAttribute('data-state', 'open');
```

## Canonical Spec Template

```ts
import { test, expect } from '@playwright/test';

test.describe('E-Commerce Checkout Journey', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('/merch');
  });

  test('should allow browsing products and adding items to cart', async ({ page }) => {
    // Verify product catalog rendered
    const productCard = page.locator('article').first();
    await expect(productCard).toBeVisible();

    // Interact with Add to Cart button
    const addToCartButton = productCard.getByRole('button', { name: /add to cart/i });
    await addToCartButton.click();

    // Verify cart drawer triggers
    const cartSummary = page.getByTestId('cart-count');
    await expect(cartSummary).toHaveText('1');
  });

  test('should enforce required delivery fields on checkout', async ({ page }) => {
    await page.goto('/merch/checkout');

    const submitButton = page.getByRole('button', { name: /confirm order/i });
    await submitButton.click();

    // Check validation error states
    await expect(page.getByText(/delivery address is required/i)).toBeVisible();
  });
});
```

## Pre-Flight Checklist Before Committing E2E Specs

1. **Isolation**: Tests must not depend on order of execution or pre-existing state in the local DB.
2. **Deterministic Cleanup**: If tests create database records, clean them up or use unique generated identifiers (e.g. `test-order-${Date.now()}@example.com`).
3. **Zero Sleep Calls**: Verify no `page.waitForTimeout(...)` calls are introduced.
